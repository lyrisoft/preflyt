# Native execution: reviewed dispatch and evidence

**Implemented:** separate runtime preflight, exact-commit source export, durable requests and worker leases, authenticated source delivery to a dedicated Docker or Kubernetes controller, private controller journals, fixed reviewed scanner execution, cancellation/restart cleanup, signed result ingestion and current published-policy evaluation. Execution defaults off and requires a current independent review plus a signed execution-capable preflight. **Remaining P3 acceptance:** complete supported-project analyzer coverage and fresh offline dependency databases, live Kubernetes acceptance, independent effective isolation review and a live release demonstration. Fixture tests do not approve connected-repository execution.

## Where to find it

Open a repository's **Assessments** tab (or the workspace Assessments page), then **Commit assessments → Execution environment → Check sandbox**. Help opens the shared drawer. The endpoint is `GET /github/repositories/:repositoryId/native-execution/status`; it requires current repository `assessment.read`. Disabled/missing/expired/changed reviews, controller outages and changed controls retain imported CI evidence. A successful preflight displays separately from check outcomes and never changes a deterministic assessment or GitHub result.

## Trust boundaries

The API and integration worker hold no Docker engine or Kubernetes control connection. `NATIVE_RUNTIME_BACKEND` selects `docker` or `kubernetes` without fallback on failed review. The base Kubernetes controller reads only named runtime resources and cannot schedule jobs with the observer RBAC. Opt-in execution uses a separate sandbox-scoped launcher identity; the observer and application identities keep their existing read-only permissions. The Docker variant uses a dedicated engine connection only in the separate controller entrypoint, for configuration observation and opted-in reviewed jobs; the trusted connection itself carries engine authority and must never point to the application host engine. It receives no database, Redis, model, GitHub or cloud-write credentials. Its entry point refuses common platform/model/SCM credential variables. It never loads the default kubeconfig, the developer's current context, an exec authentication plugin or an insecure TLS connection. No repository-supplied commands or host-container socket are used; the fixed Node test adapter executes repository test code only inside the approved isolated job.

An independent reviewer signs a deployment-scoped approval **outside Preflyt's API, worker and controller**. The controller has a different signing identity for short-lived configuration observations; it cannot manufacture an independent review. Deployers control the trusted reviewer public-key allowlist. Signatures prove who attested to a review, not that these code tests independently verified your runtime.

Kubernetes review approval is an Ed25519 compact JWS with protected `{alg:"EdDSA", kid:"reviewer-key-id", typ:"preflyt.native-runtime-approval.v1"}`. Install trusted public SPKI PEM keys as `NATIVE_RUNTIME_REVIEW_KEYS` JSON `[{"kid":"reviewer-key-id","publicKey":"-----BEGIN PUBLIC KEY-----\n..."}]`. The signed payload must contain exactly the following fields (see `NativeApproval` in source):

- `version:1`, stable `environmentId`, explicit allowed internal `organizationIds` (no wildcard).
- A dedicated `preflyt-sandbox-*` namespace name and its UID; exact runtime class name and handler `runsc` or `kata`.
- Exact `networkPolicy`, `resourceQuota`, `limitRange` and credential-free `serviceAccount` names.
- `clusterHash`: Preflyt's canonical digest of `{server:<exact HTTPS origin>,caHash:<digest of CA PEM text>}`; no default cluster fallback.
- `controlsHash`: canonical digest of `nativeControlsProjection` over the inspected namespace, RuntimeClass, all NetworkPolicies, named quota/limits and sandbox ServiceAccount. Status/volatile metadata is excluded; UIDs, security labels, worker placement, resource specifications and credential references are bound. Compute it with the same checked source version before the independent review.
- Exact HTTPS `controllerOrigin` and its Ed25519 SPKI `controllerPublicKey`.
- `approvedAt`, `expiresAt` (maximum 30 days), SHA-256 `reviewDigest` and SHA-256 `testDigests` for `escape`, `metadata`, `exfiltration`, `crossRepository`, `resourceAbuse`, `cancellation`.

These artifact digests must refer to actual independent review evidence. Do not generate dummy review certificates to enable real-repository execution. Review key removal, expiration or relevant resource changes invalidates the approval. Preflight inspects Kubernetes API or Docker engine configuration, **not effective syscall isolation, CNI enforcement, node PID limits or runtime behavior**. The independent negative tests and future per-job effective runtime checks remain required under [ADR-0002](../architecture/ADR-0002-safe-execution-fixtures-remediation-contract.md). Passing local fixtures or requested YAML does not approve a sandbox.

## Current network/resource profile

The first observer accepts one all-pod default-deny ingress/egress NetworkPolicy and rejects additional additive policies. No dependency egress profile is supported yet. RuntimeClass must select dedicated workers, namespace admission must enforce Restricted with a pinned `v1.*` policy version, and the sandbox ServiceAccount must explicitly disable token automount and contain no secret/image-pull credentials.

Quotas must bound pod count (at most 20), CPU (at most 32 cores), memory (64 GiB), storage (200 GiB) and ephemeral storage (100 GiB). Per-container limits cannot exceed 4 cores, 8 GiB memory or 4 GiB ephemeral storage; positive default requests ≤ defaults ≤ maximum are required. These are preflight ceilings, not final per-job allowances. A runtime approval still requires independent process/deadline/cancellation/resource-abuse evidence. The observer makes at most six parallel read calls, each with a 10-second abort timeout; policy inventory is capped at 100.

## Deployment and upgrade

Build the normal API runtime image; `@kubernetes/client-node` is pinned in production dependencies. The existing report proof verifier's `jose` dependency is also now included in production deployment, rather than only development dependencies. No schema migration is needed for this preflight increment.

1. Independently review a dedicated stronger runtime and retain the evidence above. Do not use an unrelated/production cluster for acceptance.
2. Use the [read-only observer RBAC example](../deployment/native-preflight/observer-rbac.yaml), replacing exact reviewed names. The controller identity can read only those objects plus list NetworkPolicies in the sandbox namespace; it cannot read secrets, exec, create Jobs or mutate resources.
3. Deploy the controller using `node dist/execution-controller.js` and the [dedicated environment example](../deployment/native-preflight/controller.env.example). Mount a least-privilege token and CA read-only. Set `NATIVE_CLUSTER_SERVER` to the exact reviewed HTTPS origin. Token rotation is supported through the mounted file; it is read for each observation.
4. Provide a separate random `NATIVE_CONTROLLER_API_KEY` of 32–256 characters to API/worker/controller, and an Ed25519 `NATIVE_CONTROLLER_SIGNING_KEY` private PEM **only to the controller**. Never install the independent review private key on either service.
5. Terminate TLS at a trusted private ingress/reverse proxy, matching the signed controller origin. Restrict ingress to the Preflyt API and worker. The [optional Compose controller example](../deployment/native-preflight/compose.yaml) binds only loopback and still requires the approved remote runtime and TLS routing; it is not an executor and does not prove sandbox isolation.
6. Install the identical signed review/public reviewer allowlist on API/controller. Set `NATIVE_PREFLIGHT_ENABLED=true` on the API (default false). Root Compose forwards the review and HTTP client configuration to API and worker, never cluster/engine credentials or the controller private key. Restart the changed services during deployment; implementation/testing does not restart your running API/worker.

Controller `GET /health/live` proves process liveness only. It deliberately does not claim executor readiness. `POST /preflight` requires the shared credential, bounded strict input and a current exact-scope independent review. It returns an Ed25519 signed observation with the caller's nonce, org, stable repository ID, approval hash, environment, time, control digest and verification failures. API verification rejects response replay, wrong scope/key/control hash, stale observations (30 seconds), redirects, excessive bodies and access/review revocation. Unknown errors are redacted. The controller serializes observations and returns 429 while busy; failed checks never suppress imported CI results.

To roll back, disable `NATIVE_PREFLIGHT_ENABLED`, remove the dedicated controller, and keep the ordinary API/CI worker. No gate/assessment/policy data or GitHub protection changes during this preflight feature's operation or rollback.

## Verification and remaining P3 acceptance

They test forged/revoked/expired/incomplete reviews, changed isolation/network/quota/credential settings, bounded controller routes, response replay/tampering, denied/revoked repository access, and the invariant that even valid preflight leaves `executionAvailable:false`. UI tests cover loaded/blocked/verified/error/loading states. No real cluster was contacted and no connected repository code was executed.

P3 release acceptance is not complete. Durable dispatch, credential-free source export, pinned fixture images, cancellation/cleanup, signed receipts and native evidence integration are implemented and fixture-tested. Remaining acceptance is supported-project coverage, fresh offline vulnerability data, real Kubernetes lifecycle testing and independently validated effective isolation. P4 work cannot turn any of these missing execution results into passing checks.

## Recorded-commit check plans

**Assessments → Commit assessments → Execution environment → View check plan** calls the scoped read-only `GET /github/repositories/:repositoryId/native-execution/plan`. It uses the latest saved profile commit and latest saved standards selection, checks repository access before/after reading and reports its full plan digest. It does not claim current branch HEAD, persist execution receipts, dispatch jobs or produce assessment outcomes. Missing inspection/standards gives a useful conflict error.

`NATIVE_TOOL_REVIEWS` is a deployment-controlled JSON array, default `[]`. An entry contains exactly `ruleId`, `image`, `toolVersion`, `license`, `configHash`, `reviewDigest`, `expiresAt`, `databaseBuiltAt`. Images must use a registry/path plus immutable `@sha256:<64 lowercase hex>`; tool versions/config/review digests are explicit. Reviews expire within 30 days; invalid/duplicate/unknown records block the entire tool inventory. For `security.dependencies`, the bundled offline vulnerability database must be at most 24 hours old. Other entries set `databaseBuiltAt:null`. This configuration records an operator-reviewed artifact; it is not independently signed runtime approval or proof that a scanner completed.

First fixed command plans cover secret scanning (Gitleaks directory scan, full redaction), dependency vulnerabilities (offline Trivy), SAST (Semgrep CE with local reviewed rules and telemetry off), and Terraform/Kubernetes policy checks (offline Trivy). All configuration/ignore paths are fixed inside the reviewed image under `/opt/preflyt/config`; no repository/model-supplied executable, argv, image tag, remote ruleset or credential environment is accepted. Plans include exact source/selection, tool-review inventory digest, image/config/review digests, command/environment, five-minute deadline, CPU/memory/storage bounds and a bounded SARIF report path. Fixed Node test and narrow Semgrep lint adapters are also implemented and fixture-tested. Build/type/coverage/container-image/exposure adapters remain unavailable in the native controller; unsupported execution never counts as passing. Trusted CI report adapters are a separate capability.

**Generated fixtures verify the exercised adapters; they do not establish broad scanner coverage or production isolation.** Pinned custom tool images must provide the exact executable/config paths, local rulepacks, writable scratch/report/cache directories and offline databases. Review image OS/architecture, scanner versions/exit semantics, ignore behavior (including repository-controlled ignores), licenses and rulepack redistribution separately. Fixture scans and effective runtime acceptance are required before these contracts may dispatch or supply native trusted evidence. An image/config digest and an operator review field alone do not establish scanner coverage or compliance.

Upstream references: [Gitleaks CLI](https://github.com/gitleaks/gitleaks), [Trivy filesystem CLI](https://www.trivy.dev/docs/latest/guide/references/configuration/cli/trivy_filesystem/), [Semgrep telemetry controls](https://github.com/semgrep/semgrep/blob/develop/metrics.md), [Semgrep engine license](https://github.com/semgrep/semgrep/blob/develop/LICENSE), [Trivy engine license](https://github.com/aquasecurity/trivy/blob/main/LICENSE). No third-party rulepack is bundled by this increment.

## Verified source export and durable requests

The internal source broker reads the exact Git commit/tree/blobs through a contents-only installation token. It checks Git SHA-1 blob and nested tree hashes, preserves binary bytes and file modes, and creates a SHA-256 bundle manifest. The receiving verifier repeats those checks. Exports reject truncated trees, unsafe paths, case collisions, symlinks, submodules, LFS pointers and oversized source. Limits are 10,000 tree entries, 2,000 files, 2 MiB per file and 20 MiB total. Cancellation stops further reads. Tokens stay in the provider broker; no public source-download route or source execution is added. The manifest proves content integrity; it is not an authenticated execution receipt. Credential-free private read-only materialization is fixture-tested. Authenticated delivery repeats bundle verification at the reviewed controller; scope-bound signed execution receipts are collected after the job.

**View check plan → Check requests** provides supported adapter selection, recorded-commit request feedback and paginated history. `POST /native-execution/requests` requires `execution.run`, an exact expected commit/selection/plan hash, selected supported rules and a UUID idempotency key. The server rechecks current scoped authority and source/standards in a serializable transaction, records request/audit together and bounds request frequency. Reusing a key with different input or actor conflicts. GET history requires `assessment.read` and rechecks access; page size is 20. Cancellation requires `execution.run`; an active external job enters `CANCEL_REQUESTED` until cleanup is confirmed. A queued request without an external job can become `CANCELLED` immediately.

**Disabled/unreviewed requests finish as BLOCKED**. Reviewed, explicitly enabled execution-capable installations queue requests for the worker. The HTTP request route itself never downloads source or executes code. The worker and dedicated controller deliver verified source, run reviewed checks, reconcile cancellation and ingest signed results. A saved assessment follows verified completion; normal current-policy authorization still governs GitHub publication. Do not treat a lifecycle label as a verified check outcome. Apply migration `20261010002000_native_execution_requests` and regenerate Prisma when deploying. Disabling preflight keeps imported CI available and preserves request audit/history.

`execution.run` is separate from `assessment.run`: Owner/Admin may request for authorized organization repositories; Security Engineer requires repository assignment. Other built-in roles cannot request/cancel native work. Fresh GitHub authority is required for GitHub-linked privileged changes. Background dispatch must reauthorize before source export, admission and result publication.

Local isolated-database tests cover permissions, origin validation, cross-tenant denial, stale plans, concurrent idempotency, pagination, membership revocation, integrity tampering and cancellation. Git-generated source fixtures cover nested trees, binary content, unsafe source and cancellation. These tests do not establish effective sandbox isolation.

Source format references: [Git objects](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects), [GitHub tree API](https://docs.github.com/en/rest/git/trees?apiVersion=2022-11-28).

## Native result receipts and policy evaluation

The internal worker result sink verifies an Ed25519 `preflyt.native-execution.v1` receipt against the independently approved controller identity. It binds request and attempt IDs, organization/repository, exact commit, source bundle hash, standards selection, admitted plan, current tool review, runtime controls and execution times. Each check identifies its immutable image, adapter, fixed command, config, tool version, report digest, bounded numeric summary, exit status, coverage and cleanup confirmation. Raw reports, messages, source snippets and logs are excluded from stored receipts.

`NativeResultService.complete` rechecks the original requester’s current membership/repository/GitHub authority and current standards. It atomically stores the signed receipt and completion audit only for the current running attempt with a live worker lease. Duplicate delivery repairs/reuses the same immutable assessment; a different receipt cannot replace it. Cancellation requires confirmed cleanup and creates no passing assessment. Expired leases, changed attempt/selection, altered request integrity and invalid signatures are rejected.

Assessment collection freezes the newest attempt for each supported native rule, including running/cancelled attempts. Publication verifies the receipt again against the current runtime/tool reviews, exact assessment scope, newest live attempt and policy age/source requirements. Full verified execution can PASS; findings/failing tests BLOCK; partial, cancelled, missing, stale, superseded or revoked evidence remains INCOMPLETE. This native proof path does not require GitHub artifact attestations and does not turn imported evidence into native results.

Apply additive migration `20261010005000_native_execution_receipts` before deploying this code and regenerate Prisma. The migration and receipt persistence are tested in an isolated temporary PostgreSQL container with `pnpm --filter @preflyt/api exec tsx scripts/native-receipt-fixtures.mts`. The local application database recovered after Docker storage cleanup; the additive receipt migration was then applied after saving a protected local backup. The unfinished AI migration was excluded. The request route queues only after current reviewed tools, explicit execution opt-in and signed controller capability pass. Otherwise it records a BLOCKED request. Do not enable repository execution based on fixture receipt tests.

## Durable Docker dispatch

Enable `NATIVE_EXECUTION_ENABLED=true` explicitly on API, worker and the dedicated Docker controller only after runtime/tool review and deployment acceptance. Set `NATIVE_PREFLIGHT_ENABLED=true` on API/worker. An older read-only controller cannot enable execution: its preflight lacks the signed `executionAvailable` capability. No deployment chooses an unsafe runtime automatically.

The worker claims PostgreSQL requests with a two-minute compare-and-set lease and a preallocated attempt UUID. It rechecks live membership, GitHub access, standards, source/plan integrity and current signed preflight. It exports the exact Git commit through a contents-only reader, passes a credential-free verified bundle over the reviewed HTTPS controller origin, then polls the same attempt. A worker restart resumes polling; it does not allocate another attempt or rerun source. Active work normally polls every five seconds. The global attempt deadline is thirty minutes, in addition to each tool's five-minute deadline. Expired or unconfirmed cleanup never produces PASS.

The controller admits at most one job at a time, with serialized admission and immutable attempt scope. Source is materialized only after a private durable journal is written. Restart recovery removes containers only after checking the exact expected scope/tool label, cleans only that attempt's private workspace and never reruns interrupted code. Signed results exclude raw reports and source. Failed cleanup retains its recovery marker and remains incomplete even if a later restart removes the resources. The journal is bounded to 1,000 attempts; retain protected terminal records according to operator retention policy, and do not delete active or cleanup-pending records. Loss/corruption of journal storage requires explicit recovery, not a rerun.

Use one controller instance per private journal directory. Precreate `NATIVE_CONTROLLER_STATE_DIRECTORY` as controller UID 1000, mode 0700, and mount it persistently. The dedicated Docker engine must see **the identical absolute path and files**; an unrelated remote filesystem will not work. Scanner containers bind only their individual read-only source directory. Engine TLS credentials, controller signing identity and journal storage remain outside scanners. No scanner can write the database or authoritative result directly. The Compose example refuses automatic creation of the state mount.

Current native coverage is deliberately conservative: reviewed directory secret scanning can provide full-rule evidence; Node builtin tests, the limited Semgrep rule, dependency and IaC adapters produce partial coverage until their complete rule coverage is established. Verified failures still block the relevant published-policy rule. A clean partial scan stays INCOMPLETE. Ordinary CI evidence remains available.

Docker application and Kubernetes application deployments can use the separate reviewed Docker controller. An operator may also select the opt-in Kubernetes-native launcher described below. Keep the observer identity read-only; the separate launcher carries execution authority.

Regression verification: real authenticated controller HTTP calls with generated source and a fixture executor, durable temporary-database queue/result tests, worker claim/resume/revocation tests, signature/policy tests, and browser status tests. No connected repository was executed or production protection changed by these tests. Disable execution flags to roll back admission; retain journals and reconcile cancellation/cleanup before stopping an active controller. No new database migration is required beyond the previously applied native request/receipt migrations.

The image-owned wrapper reconstructs the full canonical source manifest from the actual mounted bytes before and after running a tool. It checks repository/commit/hash scope supplied by the controller. Version-2 report envelopes bind that verified source hash; legacy version-1 envelopes are rejected. Rebuild, publish and independently review new immutable scanner image digests before enabling dispatch with this release. A matching remote host path alone is never accepted as source proof.

### Fixed lint and Terraform checks

The reviewed tool inventory can include `lint.required` using the same Semgrep image as security scanning, with a separate fixed `/opt/preflyt/config/lint.yaml` configuration. The initial rules catch debugger statements in JavaScript/TypeScript and bare exception handlers in Python. Repository lint configuration and scripts are never loaded. This adapter provides partial coverage: verified violations can block a gate, while clean output cannot satisfy a complete required lint check. Use verified CI evidence for the full project lint command.

Generated container fixtures verify unsafe Terraform SSH ingress, unsafe Kubernetes configuration, Python dynamic execution, and the fixed lint rules. They do not establish complete language coverage or independent runtime approval. Updating these image-owned configurations changes the image digest and requires a new tool review before deployment.

### Kubernetes job dispatch

The dedicated controller now supports opt-in Kubernetes Jobs using the same durable request journal, source scope, fixed scanner adapters and signed receipts as Docker. An immutable, bounded source ConfigMap feeds an image-owned init container. The check Pod has no service-account token, host mounts, network privileges or platform credentials. A scheduling gate holds execution until the controller validates the effective Pod, including sidecars, environment, volumes and runtime class. Cleanup checks scope ownership and uses UID preconditions.

The base observer deployment remains read-only. Execution requires the separate launcher role and explicit Compose override documented in [runner setup](../deployment/native-runner/README.md#opt-in-kubernetes-launcher). Source bundles over 512 KiB remain incomplete. Expired/changed runtime reviews block restart recovery rather than claiming successful cleanup. Simulated lifecycle tests pass, but no live cluster or independent isolation review has been accepted by these tests.
