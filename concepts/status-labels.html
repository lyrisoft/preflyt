Status labels

Every status in Preflyt has a text label as well as a colour, so meaning never depends on colour alone.

Colours​

ColourMeaning
GreenSuccess, healthy or completed
RedFailure or error
AmberNeeds attention, pending or stale
BlueInformation or in progress
GreyNot run, inactive or not available

Green marks a confirmed positive state. Related files found is green because configuration was found; it does not mean a check executed or passed. Unknown is amber and still needs attention.

Repository checks​

Shown on the repository Overview. Filter the list with All, Needs review or Files found.

LabelMeaning
Related files foundA supported file or workflow reference exists at the inspected commit. Shown in green for configuration found; it is not an execution pass.
Not foundNo supported configuration was found. This is not a policy failure.
UnknownPreflyt could not tell, for example because files were unreadable or the check is not implemented.

Check coverage in a report​

Shown per check inside a report.

LabelMeaning
Related files foundSupporting files were observed at that exact commit.
Not foundNothing associated or observed.
Source not verifiedA CI result is associated but its source is not verified.
PendingThe associated CI result had not finished.
SkippedThe associated job was not run.
Result expiredThe result was too old at the time of collection.
Report date is in the futureThe result's timestamp is later than expected, so it is not trusted as fresh.
Newer result availableA later result for the same source replaced it.
Multiple matching resultsConflicting results with the same or unknown time.
Not availableThe check adapter does not exist yet, so an association cannot enable it.

Each check in a report also has a result: Passed, Failed, Incomplete or Not evaluated.

CI results​

LabelMeaning
SucceededGitHub reported success. This does not equal a Preflyt pass.
FailedGitHub reported failure.
PendingStill running or queued.
Not runThe job was skipped or did not execute.
UnknownGitHub did not report a conclusion.

Webhook deliveries​

LabelMeaning
RecordedThe delivery was verified and stored.
Waiting to processStored, and the worker has not processed it yet.
Not processedRepository access changed before the worker processed it.
Processing failedThe worker gave up after repeated attempts. See Troubleshooting.

Merge review result​

Every report leads with one merge review result. It comes only from the saved report, so it is repeatable. It is Preflyt's view; whether GitHub allows a merge is decided by GitHub.

ResultMeaning
Required checks passedEvery check is met by observed evidence. For configuration checks this confirms configuration only.
Optional checks need attentionEvery required check passes, but an optional check does not.
Required checks failedA required check has a failed result from an approved, verified CI source at that commit.
Required results incompleteRequired evidence is missing, stale or unverified, collection was truncated, or the policy has no required checks.

Results that Preflyt cannot verify stay incomplete. They never become a pass.
