Configuration

Preflyt splits configuration in two:

  1. Settings → Configuration in the web app holds application connections and feature switches. Only a Super Admin can change them. They apply to every workspace.
  2. Environment variables hold everything that must exist before the database can be read: infrastructure, encryption keys and trust controls.

What lives in Settings​

Open Settings → Configuration as Super Admin.

SectionWhat you configure
GitHubPublic Preflyt API URL, App ID, client ID and secret, private key, webhook secret, installation and login callbacks, the sign-in switch and the event-ingestion switch
GovernanceAn optional separate governance App and installation ID, automatic PR check publication, ruleset activation, history import and retention
Single sign-onOIDC issuer, client ID and secret, callback
NotificationsIn-app and email switches, SMTP host, port, sender, username and password
IntelligenceModel configuration and advisory review switches
Native executionPreflight and execution switches

Organization-level settings stay on their own pages: AI models and provider keys, review skills, CI jobs and policies, notification channels, and Settings → PR feedback (PR check publication, policy summary comments and optional AI feedback). Organization Owners and Admins cannot change deployment credentials.

How saved settings behave​

  • Secrets stay hidden. The browser never receives a saved secret, only whether one is set. Leave a secret field empty to keep the saved value. Use Clear saved and then Save changes to remove it.
  • GitHub connections refresh safely. GitHub and optional governance credentials apply immediately in the API and within five seconds in the worker. Cached App clients and installation tokens refresh when the App key changes. OIDC and SMTP connections still require an API and worker restart; the page shows a restart notice for those changes.
  • Feature switches apply on their own. Switches and history retention refresh every five seconds, with no restart.
  • Concurrent edits are detected. If someone else saved first, refresh and re-apply your change.
  • Changes are audited. The audit record stores who changed which fields and the revision, never secret values.
  • Failures fail closed. If a read or decryption fails, live switches turn off until a read succeeds. Preflyt does not fall back to old environment values.

Environment-file edits are different: use docker compose up -d to recreate affected services. docker compose restart does not reload .env.

First start and legacy values​

On first start the API imports any application values it finds in the environment once, encrypts the secrets and stores them. After that, database values always win, including empty ones. On a fresh install you can leave the application values out and fill them in under Settings. You will first need the Super Admin recovery login to open the page. See Authentication.

What stays in environment variables​

Keep these in your .env or secret manager:

  • database and migration passwords,
  • cache and queue URLs and prefixes,
  • the public origin and HTTP port,
  • the Super Admin recovery credentials and bootstrap token,
  • telemetry,
  • the three encryption keys,
  • native execution, CI proof and attestation trust settings.

The three encryption keys​

Generate three separate 32-byte base64 keys with openssl rand -base64 32:

KeyProtects
CONFIGURATION_ENCRYPTION_KEYCredentials saved in Settings → Configuration
GITHUB_USER_TOKEN_ENCRYPTION_KEYGitHub user tokens used for GitHub sign-in
AI_PROVIDER_ENCRYPTION_KEYAI provider credentials

Never reuse one key for another purpose, commit a value, or paste a key into Settings. Back up each key in your secret manager, independently of the database. There is no key rotation: if you replace a key, restore the original to decrypt what it protected.

Variable reference​

Defaults are what Preflyt uses when you do not set a value. A blank default means the value is unset. You only need to set the variables in the Docker Compose guide to get started.

Recovery and sign-in​

VariableDefaultDescription

Cache and queue​

VariableDefaultDescription
REDIS_URLredis://cache:6379/0Metadata cache. Override only for a separately managed service.
REDIS_CACHE_PREFIXpreflyt:production:cacheKey prefix for the cache.
QUEUE_REDIS_URLredis://queue:6379/0Job queue. It must not evict keys.
QUEUE_PREFIXpreflyt:production:queueKey prefix for the queue.
Keep the queue separate

The cache evicts under memory pressure. The queue must use noeviction with persistence. Do not point both at the same evicting instance. Different Redis database numbers do not isolate memory.

CI evidence and governance trust​

Normal Action onboarding verifies the GitHub run, attempt, commit and completed jobs directly through the GitHub App. Report signatures are optional, including for private repositories; no GPG key or external signer is required. The variables below configure additional signed-report verification for deployments that explicitly use it. See the advanced trust runbook; it is not the basic onboarding path.

VariableDefaultDescription
CI_REPORT_PROOF_MODEgithub-nativeVerification of optional report signatures: GitHub attestations (github-native) or a configured organization signer (organization-key). Neither is required for the normal GitHub job-verification path.
CI_ORGANIZATION_SIGNER_KEYSPublic-key allowlist JSON. Never include private keys.
CI_ATTESTATION_GH_PATHAbsolute container path of the reviewed GitHub CLI executable used to verify attestations.
CI_ATTESTATION_GH_SHA256SHA-256 of that exact binary, lowercase hexadecimal.
CI_ATTESTATION_ROOT_PATHAbsolute container path of the reviewed Sigstore trusted-root file.
CI_ATTESTATION_ROOT_SHA256SHA-256 of that exact file, lowercase hexadecimal.
CI_ATTESTATION_WORKFLOWSJSON array of exact signer workflow paths, owner/repo/.github/workflows/file.yml.
CI_EXECUTION_CONTRACTSReviewed JSON array of contracts. Each pins a rule ID, signer workflow, reviewed commit, report format and tool version. Set by the deployer, never by users.
PREFLYT_ATTESTATION_DIRHost directory mounted by the reviewed evidence Compose override.
GITHUB_GOVERNANCE_LOCAL_ACCEPTANCEfalseMust stay false in production. For disposable local acceptance only.

Native execution​

Native execution is disabled by default and needs its own reviewed controller. See Native execution for prerequisites, supported adapters and remaining acceptance limits.

VariableDefaultDescription
NATIVE_RUNTIME_BACKENDkubernetesExplicit runtime backend: kubernetes or docker. No fallback after failed review.
NATIVE_DOCKER_APPROVALSigned independent approval for the Docker backend; use instead of a Kubernetes runtime approval.
NATIVE_RUNTIME_APPROVALA signed independent review of the execution runtime (an Ed25519 signed token). It expires within 30 days.
NATIVE_RUNTIME_REVIEW_KEYS[]JSON array of trusted Ed25519 public keys (kid and PEM) that verify that review.
NATIVE_CONTROLLER_API_KEYRandom key of 32 to 256 characters shared by the API, worker and execution controller.
NATIVE_TOOL_REVIEWS[]JSON array of reviewed tools: rule, image pinned by @sha256: digest, version, licence, configuration hash and expiry (at most 30 days). Repository-supplied commands are never accepted.
